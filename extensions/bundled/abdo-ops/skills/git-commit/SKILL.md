# الإيداع — ما فعلتَه أنت، كما هو، بلا زيادة

## 1. اقرأ الحالة

`git status` و`git diff --stat` — اعرف ما الذي تغيّر، ومن غيّره. ملفٌّ لم تلمسه في هذه المهمّة **ليس لك**: لا تدرجه.

## 2. أدرج ملفّاتك بأسمائها

- `git-stage <ملف> <ملف>` — **لا `git add -A` ولا `git add .`** أبداً: يجرّ عملَ جلسةٍ أخرى وملفّاتٍ مؤقّتة وأسراراً.
- لا تدرج: `.env*`، المفاتيح، `*.log`، `node_modules`، مخرجات البناء، ملفّات قواعد البيانات المحلّية. المحرّك يرفض إدراجَ ملفّ أسرار.

## 3. راجع المُدرَج قبل الإيداع

`git diff --cached` — اقرأه كلَّه:
- سرٌّ أو رمزٌ أو كلمةُ مرور؟ ⇦ أخرجه وانقله إلى الخزنة.
- سطرُ تشخيصٍ منسيّ (`console.log`، `debugger`)، أو اختبارٌ عُطّل (`.skip`)؟
- نهاياتُ أسطر انقلبت في ملفٍّ كامل (CRLF/LF)؟ فرقٌ بحجم الملفّ لتعديل سطرٍ واحد = خطأ.

## 4. الرسالة

- سطرٌ واحد قصير بصيغة الأمر يقول **ما تغيّر**: `fix login redirect after session expiry`.
- لا ادّعاءَ لم يُقس («all tests pass» تُكتب فقط إن شغّلتها في هذا الدور ونجحت).
- لا أسماءَ أشخاص ولا معلوماتٍ داخليّة في مستودعٍ عامّ.

## 5. أودِع

`git-commit <الرسالة>` — محلّيّ، بلا دفع. ثمّ `git log --oneline -1` و`git status` لتتأكّد أنّ الشجرة كما توقّعت.

الدفعُ خطوةٌ منفصلة لها مهارتُها (git-push) وموافقتُها.
