# الدفع — قد يكون نشراً، فعامله كذلك

## 1. ما الذي سيُدفع؟

```
run git status -sb
run git remote -v
run git log --oneline @{u}..HEAD
```

- الفرعُ الحاليّ، والبعيد، وقائمةُ الإيداعات التي ستخرج — اعرضها للمستخدم.
- إيداعاتٌ ليست من هذه المهمّة في القائمة؟ ⇦ توقّف واسأل؛ لا تدفع عملَ غيرك.

## 2. اجلب وقارن قبل الدفع

```
run git fetch origin
run git log --oneline HEAD..@{u}
```

- البعيدُ متقدّم ⇦ ادمج أو أعد التأسيس محلّياً، ثمّ ابنِ واختبر من جديد، ثمّ ادفع. **لا تدفع نسخةً أقدم من البعيد.**
- تحقّق بالمحتوى لا بالنسب: ملفٌّ مهمّ يختلف عن البعيد؟ قارنه (`git diff @{u} -- <ملف>`).

## 3. الموافقة

- **كلُّ دفعٍ يحتاج موافقةَ المستخدم** — المحرّك يسأل دائماً عند `git push`.
- إن كان الفرعُ مربوطاً بنشرٍ تلقائيّ (main في أغلب المشاريع المستضافة) فقل ذلك صراحةً: «هذا الدفع ينشر للإنتاج».

## 4. الدفع

- `run git push origin <الفرع>` — **لا `--force`**؛ إن رُفض الدفع فالبعيد تغيّر: عُد إلى الخطوة 2.
- لا تتجاوز الخطّافات (`--no-verify`) — خطّافٌ فشل يقول شيئاً يجب إصلاحه.

## 5. بعد الدفع

- `run git status -sb` يجب أن يقول إنّ الفرعَ متزامن.
- إن كان للمستودع CI: انتظر نتيجته واذكرها؛ وإن نشر تلقائياً فافحص الرابطَ الحيّ (مهارة verify-delivery).
