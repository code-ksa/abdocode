# الحزم — القفلُ عقد، والإضافةُ قرار

## 1. اعرف مديرَ الحزم من القرص

- `package-lock.json` ⇦ npm · `pnpm-lock.yaml` ⇦ pnpm · `bun.lock` أو `bun.lockb` ⇦ bun · `yarn.lock` ⇦ yarn.
- لا تخلط مديرَين: تثبيتٌ بـnpm في مشروع pnpm يكتب قفلاً ثانياً ويكسر البناء على الخادم.

## 2. التثبيت

- نظيفٌ ومطابقٌ للقفل: `npm ci` (أو `pnpm install --frozen-lockfile`، `bun install --frozen-lockfile`).
- `npm install` يغيّر القفل — استعمله فقط حين تضيف أو تحدّث حزمةً عمداً.

## 3. قبل أن تضيف حزمة

- هل في المشروع أو في المكتبة القياسيّة ما يكفي؟ (`fetch`، `crypto.randomUUID`، `node:test`، `structuredClone`…)
- اقرأ ما يُثبَّت: `npm view <حزمة> version license dependencies` — حزمةٌ مهجورة أو برخصةٍ غير متوافقة تُقال للمستخدم.
- `npm install <حزمة>@<إصدار>` بإصدارٍ محدّد، و`-D` لأدوات التطوير.

## 4. الترقية

- **لا ترقيةَ كبرى (major) بلا سبب مكتوب** — Next وReact وPrisma وTailwind تكسر الواجهات بين الإصدارات الكبرى. المحرّك يرفض أمرَ ترقيةٍ كبرى إلا بتعليقٍ يذكر السبب: `# major-upgrade: <السبب>`.
- رقّ حزمةً واحدة، ثمّ ابنِ واختبر، ثمّ التالية — لا عشر حزمٍ في أمرٍ واحد.
- `npm outdated` يقرأ ولا يغيّر؛ ابدأ به.

## 5. الثغرات

- `npm audit --omit=dev` — الثغراتُ في حزم الإنتاج أولى.
- `npm audit fix` مقبول؛ **`npm audit fix --force` ممنوعٌ بلا موافقة** — يرقّي ترقياتٍ كبرى صامتة.

## 6. حزم النظام

- أوبونتو: `apt-get install -y --no-install-recommends <حزمة>` بأسماءٍ صريحة؛ ويندوز: `winget install --id <معرّف> -e`.
- بعد كلّ تثبيت: `<أداة> --version` دليلٌ لا نجاحُ المثبِّت.

## 7. التسليم

اذكر: ما أُضيف وما حُذف وما رُقّي (بالإصدارين)، ولماذا، ونتيجةَ البناء والاختبارات بعده.
