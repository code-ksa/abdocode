# التحقّق قبل الادّعاء

## القاعدة

**لا ادّعاءَ بلا قياسٍ أُخذ في هذا الدور.** «بنيتُه»، «يعمل»، «نُشر»، «الاختبارات تمرّ» — كلٌّ منها يحتاج إيصالاً تراه أنت الآن، لا ما تتذكّره ولا ما كتبه أحدٌ في ملفّ.

## 1. لكلّ ادّعاءٍ دليلُه

| الادّعاء | الدليل |
|---|---|
| الكود يُبنى | `run npm run build` — خروجٌ 0 في هذا الدور |
| الاختبارات تمرّ | `run npm test` — العددُ والنتيجة |
| الملفّ كُتب صحيحاً | `read <ملف>` بعد الكتابة — المحتوى على القرص لا ما أرسلتَه |
| الصفحة تعمل | الخادمُ المُدار + `open` + `shot`، و`audit` للواجهة |
| نُشر | `deploy … --check <رابط>` بحالة 2xx، أو `curl -fsS` من الخادم |
| الخدمة حيّة | العمليّةُ التي تستمع (`ss -ltnp` / `pm2 jlist`) لا ملفُّ الإعداد |

## 2. اسأل القرصَ لا الدالّة

الدالّةُ التي تعيد «ok» قد تنسى حقلاً. الفحصُ الحاكم يقرأ الملفّ المكتوب، أو صفَّ قاعدة البيانات، أو استجابةَ HTTP — بعد تشغيل المسار الحقيقيّ كما يشغّله المستخدم.

## 3. الأخضرُ قد يعني «لم يحدث شيء»

نتيجةٌ نظيفة من فحصٍ لم يُستدعَ مسارُه كذبةٌ خضراء. تأكّد أنّ المسار نُفّذ فعلاً (سطرٌ في السجلّ، عدّاد، ملفٌّ تغيّر).

## 4. الحيُّ يتأخّر عنه الملخّص

ما قرأتَه قبل ساعة قد تغيّر. قبل أن تبني على حالةٍ قديمة: أعد قراءتها (`git log -3`، `git status`، الملفّ نفسه).

## 5. قل ما لم يُنجز

- ما فشل: بنصّ الخطأ. ما تُرك: باسمه وسببه. ما لم تستطع التحقّق منه: «لم أستطع إثباته» — **غيابُ الدليل ليس نجاحاً**.
- لا تخفّف الفشل ولا تضخّم النجاح؛ والوثيقةُ التي تقول «لم يُنفَّذ» لشيءٍ نُفّذ خطأٌ كالعكس.

## 6. شكلُ التسليم

1. ما الذي طُلب.
2. ما الذي فُعل — بالملفّات.
3. الإيصالات — الأوامرُ ونتائجها المقيسة في هذا الدور.
4. ما بقي أو فشل، وما الخطوة التالية.
