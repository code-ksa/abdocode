### 15.v المُشغّل العاري في الخادم المُدار رمى ENOENT فأسقط الدور (Next، 2026-09-02)
جولة qwen3.8-max الحية (الدور `e2e-1788296470333`) وصلت الحقبة 2: النموذج
كتب المشروع ونجح `npm install` و`npm run build` عبر أداة run (تمرّ على
powershell الذي يحلّ npm.cmd)، ثم أمر `npm start` فوجّهه parseServerCommand
إلى الخادم المُدار — و`Bun.spawn(["npm","start"])` **رمى** `ENOENT: uv_spawn
'npm'`. الرمية لم تُلتقط في `start`، فأفلتت إلى catch الدور (cli.ts:2690)
فأصدرت `refused` فعدّها هارنس e2e سقوطاً قاتلاً وخرج برمز 1 — الجولة كلها
ماتت على أمرٍ واحد.
**عطلان متراكبان (نمط 15.w نفسه)**:
1. **فشل مفتوح**: رميةُ إطلاق خادمٍ تُسقط الدور بدل أن تصير إيصالاً. كل
   فشل أداةٍ آخر إيصالٌ يتصرّف النموذج تجاهه؛ هذا وحده كان قاتلاً.
2. **اسمٌ عارٍ هشّ**: `npm` العارية تعتمد حلّ PATH×PATHEXT الضمني في بيئة
   Bun — بينما أداة run تمرّ على powershell المطلق فتحلّه دائماً. **لم
   يُعَد إنتاج ENOENT بالـPATH الملتقط لاحقاً** (npm يُحلّ عليه)، فالمُحفّز
   بيئيٌّ عابر لا يُثبَّت — وهذا بالضبط سبب أن الاسم العاري سطحٌ هشّ.
**القضيب (طبقتان، managed-server.ts)**:
- `resolveLauncher` يحلّ npm/npx/pnpm/yarn/node/bun/next إلى مسارٍ مطلق
  موجود (المواضع القانونية أولاً: `%ProgramFiles%/nodejs` ثم PATH ثم
  `%APPDATA%/npm`)، والغياب يُترك للنظام — نفس درس system-tools 6.3
  ممتداً لعائلة node.
- `start` تلفّ `Bun.spawn` في try/catch: فشل الإطلاق إيصالٌ
  `فشل تشغيل الخادم «…»: تعذّر إطلاقه — …` (يحمل «فشل» فيصنّفه
  toolReceiptFailed فشلاً قابلاً للتصرّف)، لا رمية.
**البوابة**: اختباران في managed-server.test.ts — «مُشغّلٌ لا يُطلَق يعيد
إيصالاً ولا يرمي» (كان يرمي قبل الإصلاح) وحلّ resolveLauncher؛ المحرّك
‏278/0.
